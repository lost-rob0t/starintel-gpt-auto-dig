This schema change is reviewed as one coordinated draft set. None of these branches may be merged automatically.

## Compatibility rules

- Legacy Python subtype constructors remain available, but package import installs the canonical v0.9 `to_dict()`, `to_json()`, `asdict()`, and `to_schema_org()` methods on every document subclass so dataclasses-json decorators cannot flatten the wire envelope.
- Common Lisp and Nim retain subtype slots or object fields in memory while their wire codecs nest those values under `data`.
- JavaScript materializes the revisioned canonical schema bundle and derives `schema_uri` directly from the generated schema `$id`.
- Server ingestion accepts only canonical v0.9 envelopes at HTTP and RabbitMQ boundaries and keeps temporary legacy read fallbacks in CouchDB views.

## Review order

1. Confirm canonical dtype fields and the strict `schema_org` block in auto-dig.
2. Confirm JSON Schema generation and idempotent corpus enrichment.
3. Review the JavaScript, Python, Common Lisp, and Nim wire representations.
4. Review server ingestion, routing, CouchDB view migration, and dependency pins.
5. Run every current CI check against each current PR head.
6. Manually approve and merge in dependency order only after explicit confirmation.

Recommended dependency order after confirmation:

1. `starintel-gpt-auto-dig`
2. `starintel-doc`, `star-cl`, `starintel-doc.nim`, and `starintel_doc.js`
3. `starintel-server`

The branches remain draft until all cross-language checks are green and the user confirms each PR.
